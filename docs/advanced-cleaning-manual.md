# Ручная проверка Advanced Cleaning (этап 4A)

Это инструкция для проверки в графической сессии, а не утверждение о выполненной
ручной проверке. Данные вымышленные, адреса используют домен `.invalid`.

```bash
source .venv/bin/activate
python examples/generate_advanced_samples.py
python -m excel_toolkit
```

В `examples/generated/stage4a/` появятся `advanced_cleaning_demo.xlsx` и
`advanced_cleaning_demo.csv`. Повторный запуск не изменяет существующие файлы.
Для нового комплекта можно указать `--output-dir /tmp/advanced-cleaning-new`.
CSV использует UTF-8 с BOM и `;`. В XLSX два листа: Clients и Headers, оба с freeze A2.

Заголовок в строке 1: `ID`, `Name`, `City`, `Email`. Счётчики включают заголовок.

## All Columns и Selected Columns

1. Откройте XLSX, лист Clients. Оставьте четыре операции включёнными и All Columns.
   Выполните Analyze & Clean. Сравните отчёт с таблицей ниже.
2. Переключите Selected Columns, отметьте только `A — ID`. Старый результат и Issues
   должны очиститься, Save Cleaned File стать недоступной. Выполните новый анализ.
3. Проверьте, что сохранились **обе** записи ID `00123` (исходные 2 и 3, Astana / Almaty),
   **обе** записи ID `00999` (13 и 14, включая заполненный Email),
   **обе** записи с пустым ID (исходные 6 и 7), ID `abc`
   и `ABC` различаются, а `00123`, `00007`, `00042`, `00000` сохранили ведущие нули.
4. Повторите с ключами ID + City: результат тот же, но конфликт по City исчезает,
   поскольку строки 2 и 3 попадают в разные группы ключей.

| Показатель | All Columns | Только ID | ID + City |
| --- | ---: | ---: | ---: |
| Original Rows | 15 | 15 | 15 |
| Cleaned Rows | 11 | 12 | 12 |
| Removed Empty Rows | 1 | 1 | 1 |
| Removed Duplicates | 3 | 2 | 2 |
| Trimmed Cells | 5 | 5 | 5 |
| Missing Values | 4 | 6 | 6 |
| Найденные группы повторяющихся ключей | 3 | 4 | 3 |
| Конфликтующие группы | 0 | 2 | 1 |
| Missing Key Rows | 0 | 2 | 2 |
| Issues | 4 | 6 | 6 |

Сохраняемые **исходные** номера строк:

- All Columns: `1, 2, 3, 4, 6, 8, 9, 10, 13, 14, 15`.
- Только ID: `1, 2, 3, 4, 6, 7, 8, 9, 10, 13, 14, 15`.
- ID + City: `1, 2, 3, 4, 6, 7, 8, 9, 10, 13, 14, 15`.

При ключе ID конфликтные группы имеют статус **Conflict — Needs Review**:
сохранены 2 и 3 (City: Astana / Almaty), сохранены 13 и 14 (Email: пусто /
`lee@example.invalid`). Автоматически удалены только идентичные записи:
Keep 4 / Remove 5 и Keep 10 / Remove 11 после Trim. Все номера исходные.
Значения показывают результат Trim, вкладка Original Data сохраняет исходные пробелы.
Пропуски не заполняются; более полная запись не выбирается вместо другой.
All Columns удаляет строку 7 как полное совпадение; защита пустых ключей относится
именно к Selected Columns. Пустая строка 12 удаляется раньше поиска дубликатов.

## Issues и изменение параметров

В режиме ID ожидаются шесть проблем: `4/D Missing Value`, `6/A Missing Key`,
`6/D Missing Value`, `7/A Missing Key`, `7/D Missing Value`, `13/D Missing Value`.
В очищенной таблице исходная строка 13 находится в строке 10, но Issues показывает 13.
Выключите Detect Missing Values и повторите анализ: останутся два Missing Key
из строк 6 и 7, Missing Values будет 0; остальные результаты очистки сохранятся.

Снимите все отметки ключей при включённом Remove Duplicates: анализ должен сообщить
об ошибке выбора, экспорт недоступен. Верните ID; меняйте ключи после анализа и
проверяйте, что предыдущий результат нельзя сохранить. Отключите Trim и повторите:
при одном ID будет 13 итоговых строк, 1 удалённый дубликат, 1 конфликт и 0 обрезанных ячеек.

Переключите лист Headers: список обновится до `A — ID`, `B — Name`, `Column C`,
`D — Name`; дубликаты заголовков не связывают отметки B и D. При всех операциях и
единственном ключе B получите 3 строки и одну сохранённую конфликтную группу; при ключе D —
3 строки и ни одного дубликата. Пустой заголовок C1 отображается как Missing Value.
Вернитесь на Clients и выполните новый анализ: экспорт результата другого листа
не должен оставаться доступным.

## Безопасный экспорт

1. Восстановите четыре операции, Selected Columns, ключ ID. После анализа нажмите
   Save Cleaned File и отмените выбор имени: файл не создаётся, результат остаётся
   доступным для просмотра и повторной попытки.
2. Выберите свободное имя, например `manual_id_safe_cleaned.xlsx`. Результат
   экспортируется без общего Yes/No для удаления конфликтов. Предупреждение должно
   сообщать, что **2 конфликтующие группы сохранены и остаются неразрешёнными**.
3. Ожидаются 12 строк с заголовком, оба города у ID `00123` и обе записи ID `00999`,
   включая пустой и заполненный Email. Повторно откройте экспорт и запустите тот же
   анализ: 12 строк, 0 удалений дубликатов, 2 конфликтные группы и 2 Missing Key Rows.
   Для будущего разрешения конфликтов потребуется выбор конкретных строк или значений;
   сейчас общего подтверждения удаления конфликтных вариантов нет.
4. Откройте экспорт в Excel/LibreOffice. Проверьте freeze A2, строковые ID и
   неизменный лист Headers. Исходный файл должен сохранить исходные 15 строк.
   Сохранение поверх исходного или занятого имени должно быть отклонено.
5. Повторите для CSV; числа совпадают. При импорте в Calc задайте разделитель `;`
   и тип **Текст** столбцу ID, иначе Calc может сам убрать ведущие нули.

Отмена диалога не отменяет уже начатую запись. Отдельной кнопки отмены анализа/
экспорта нет; закрытие занятого окна ожидает завершения. Во время фоновой работы
интерфейс должен перерисовываться; проверьте прокрутку и размеры окна 760×540 и 1100×900.

Для больших входов Issues ограничены 100, группы — 100, примеры удалений в группе — 20;
показывается первая сохранённая строка и до 20 дополнительных сохранённых вариантов.
Сообщения об усечении должны сохранять полные количества; конфликты за пределами
видимой выборки тоже сохраняются и учитываются в предупреждении. Поддержка сложных XLSX не расширена:
книга с featurePropertyBag должна дать объяснимый отказ, сохранив оригинал и запретив
экспорт. Не удаляйте этот компонент пересохранением через openpyxl ради обхода проверки.
