# Excel Freelancer Toolkit

Локальное desktop-приложение для Linux на Python 3.11+, PySide6 и openpyxl.
Этап 4A: предпросмотр, независимый движок Cleaner, выбор ключей дубликатов и Issues в GUI.
Сервер, внешние API, платные сервисы, pandas и ИИ не используются. Интернет нужен только для установки зависимостей.

## Возможности

- Раздел Cleaner: выбор `.xlsx` / `.csv`, листа Excel, имя файла и область ошибок.
- Вкладки **Original Data / Cleaned Data**: первые **100 строк**, включая заголовок.
  Анализ и экспорт обрабатывают полный поддерживаемый файл.
- До **200 столбцов**; наличие дополнительных строк/столбцов отмечается в интерфейсе.
- Чтение, анализ и экспорт в Qt-потоке, неопределённый индикатор выполнения,
  безопасное ожидание завершения операции при закрытии.
- CSV: UTF-8 с BOM и без; ручной выбор Windows-1251, Windows-1252 и UTF-16 с BOM.
- Разделители: запятая, точка с запятой, табуляция, `|`; автоопределение или ручной выбор.
- Формулы XLSX показываются как текст и не вычисляются. Значения CSV остаются строками.
- Четыре независимые операции очистки, отчёт **Cleaning Summary** и сохранение в новый файл.
- **All Columns / Selected Columns**: поиск дубликатов по всей строке или выбранным
  столбцам, подробности групп, защита пустых ключей и сохранение конфликтных вариантов.
- Вкладка **Issues**: пропуски и отсутствующие ключи с номерами исходных строк.
- Оригиналы открываются только для чтения. GUI и Python API используют один движок.
  Merger и Compare пока недоступны.

## Установка в Linux

Нужен Python 3.11+ с поддержкой `venv`. В Arch Linux системный пакет называется
`python`; зависимости проекта устанавливаются в отдельное окружение:

```bash
cd /path/to/prog-excel
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

Без инструментов разработки: `python -m pip install -e .`.
Системное окружение Python менять не требуется. Зависимости и настройки проверок —
в `pyproject.toml`.

## Запуск

В активированном окружении, из терминала графической сессии Linux:

```bash
python -m excel_toolkit
```

Нажмите «Выбрать файл…». У XLSX с несколькими листами станет доступен список листов.
Для CSV по умолчанию используются UTF-8 и автоопределение разделителя. Если файл
не прочитан или разделитель распознан неверно, выберите настройки и нажмите
«Повторить загрузку» либо запустите анализ с новыми параметрами.
Настройки применяются и при следующем выборе файла.
Ошибочные байты не заменяются и не пропускаются.

Создание примеров без перезаписи существующих файлов:

```bash
python examples/generate_samples.py
```

Для проверки очистки откройте `examples/generated/cleaner_demo.xlsx` (лист «Клиенты»)
или `cleaner_demo.csv`. Файлы `clients.xlsx` / `clients.csv` демонстрируют исходный
предпросмотр; у `clients.xlsx` есть формула. Для `clients_cp1251.csv` выберите Windows-1251.

## Очистка через GUI

1. Выберите XLSX/CSV. При необходимости выберите лист, кодировку и разделитель.
   **Original Data** показывает исходные значения, включая пробелы и ведущие нули.
2. В блоке «Операции очистки» включите нужные checkbox. В GUI все четыре операции
   **включены по умолчанию**: Trim Whitespace, Remove Empty Rows, Remove Duplicates,
   Detect Missing Values. Первая строка считается заголовком. Порядок операций фиксирован.
   Для дубликатов по умолчанию выбран **All Columns**; в **Selected Columns** отметьте
   хотя бы один ключевой столбец. Подробности режима описаны ниже.
3. Нажмите **Analyze & Clean**. Движок анализирует полный файл без записи в оригинал.
   Пока выполняется задача, появляется индикатор без процентов, кнопки запуска и
   настройки блокируются. Интерфейс продолжает обрабатывать события.
4. После завершения откроется **Cleaned Data**. Переключайтесь на **Original Data**
   для сравнения. Обе вкладки показывают первые 100 строк одного снимка анализа,
   до 200 столбцов; скрытое продолжение явно отмечено. Таблицы доступны только для чтения.
5. В **Cleaning Summary** проверьте Original Rows, Cleaned Rows, Removed Empty Rows,
   Removed Duplicates, Trimmed Cells и Missing Values. Ниже показаны выполненные операции
   и предупреждения отчёта, сведения о дубликатах и отсутствующих ключах. Во вкладке
   **Issues** доступны исходные координаты пропусков. Пропуски не заполняются.
6. Нажмите **Save Cleaned File…** и выберите **новое имя**. Диалог предлагает суффикс
   `_cleaned` и только исходный формат. Если расширение не введено, оно добавляется.
   Существующий файл и оригинал нельзя заменить; конвертация XLSX/CSV не предлагается.
   Экспорт также выполняется в фоне. После успеха появится полный путь для копирования.
   При конфликтах вне ключевых столбцов все отличающиеся варианты сохраняются;
   предупреждение показывает число неразрешённых конфликтующих групп.
7. Если изменён выбранный файл, лист, кодировка, разделитель, checkbox, режим дубликатов
   или выбранные ключи, результат,
   отчёт и доступ к экспорту сбрасываются. Перед сохранением нужен новый анализ.
   Повторная загрузка также сбрасывает результат. Отмена файлового диалога его сохраняет.

При отказе проверки безопасности исходный предпросмотр остаётся доступен, а экспорт
блокируется. Полная причина отображается в прокручиваемой области ошибок; окно
автоматически прокручивается к сообщению. Ошибка экспорта не отображается как успех:
можно выбрать новое имя и повторить сохранение рассчитанного результата.
На небольших окнах доступна прокрутка всей рабочей области.

Отдельной кнопки отмены нет. Закрытие во время анализа/экспорта **ждёт завершения**,
не уничтожая поток и не прерывая запись. При закрытии во время экспорта новый файл
может быть успешно сохранён до закрытия окна. Предпросмотр поддерживает существующую
кооперативную отмену. Принудительное завершение процесса не заменяет безопасное закрытие.

## Advanced Cleaning: ключи, дубликаты и Issues

**All Columns** сохраняет прежнее поведение: удаляются только полностью совпадающие
строки. **Selected Columns** сравнивает отмеченные столбцы, например только `A — ID`
или `A — ID` вместе с `C — City`. Внутри группы одинаковых ключей удаляются только
полностью совпадающие после включённых нормализаций записи. Сохраняется первое вхождение
каждого отличающегося варианта и исходный порядок строк.
Регистр и тип значения учитываются; `abc` и `ABC`, число `1` и `True`
различаются. Текст `00123` остаётся текстом с ведущими нулями. Trim выполняется первым.

Список ключей использует позиции столбцов, а не названия: одинаковые заголовки
`B — Name` и `D — Name` независимы, пустой заголовок обозначается `Column C`.
При смене файла или листа список обновляется. Selected Columns без отмеченных ключей
при включённом Remove Duplicates не допускается. Предпросмотр собирает заголовки
целиком; дополнительные столбцы без заголовков, встречающиеся только после первых
100 строк, станут доступны после полного анализа в режиме All Columns.

В Selected Columns строка с пропуском хотя бы одного ключа **сохраняется для проверки**,
даже если другая строка выглядит точно так же. Пустота — `None`, отсутствующее поле,
пустой или пробельный текст; `0` и `False` не пусты. Эта защита относится к выбранным
ключам: All Columns сохраняет прежнее сравнение всей строки. **Remove Empty Rows
выполняется раньше**, поэтому полностью пустая строка по-прежнему может быть удалена.

Анализ дубликатов разделяет найденные повторяющиеся ключи, автоматически удалённые
идентичные записи (**Remove**) и сохранённые варианты (**Keep**) с исходными номерами
и примерами значений. Если у одинаковых ключей различаются остальные значения,
группа имеет статус **Conflict — Needs Review**; показаны различающиеся столбцы.
Например, один ID с разными City сохраняет обе записи. Пустой Email и заполненный
Email также сохраняются отдельными вариантами. Пропуски не заполняются автоматически.
Безопасный результат экспортируется в новый файл с предупреждением о неразрешённых
конфликтах; общего **Yes**, разрешающего удалить конфликтные варианты, нет.
В Python API достаточно `service.export(job, new_path)`. Параметр `confirm_conflicts`
оставлен для совместимости и не изменяет результат. Для будущего ручного разрешения
конфликтов понадобится выбор конкретных строк или значений.

**Issues** показывает номер **исходной** строки, столбец и тип проблемы. Обычные
**Missing Value** ищутся в итоговых строках при включённом Detect Missing Values.
**Missing Key** собираются для выбранных ключей даже при отключённой общей проверке
пропусков. Одна ячейка не дублируется двумя проблемами: Missing Key имеет приоритет.
Missing Values считает ячейки, Missing Key Rows — строки с хотя бы одним пустым ключом.
Пропуски удалённых строк в итоговый список не входят; пустые ячейки заголовка могут
быть Missing Value, но не Missing Key. Значения автоматически не заполняются.

GUI показывает до **100 Issues**, **100 групп дубликатов** и **20 примеров удалений
в каждой группе**. При усечении показано, какая часть доступна; итоговые счётчики и
проверка конфликтов относятся ко всему файлу. Вкладки используют готовый отчёт,
повторный анализ при переключении не запускается.
В описаниях групп длинные значения сокращаются до 100 символов, общий текст
подробностей ограничен 300 000 символов; сами значения в результате не обрезаются.

Синтетические XLSX/CSV с ожидаемыми числами и сценариями проверки:

```bash
python examples/generate_advanced_samples.py
```

Файлы появятся в `examples/generated/stage4a/`; повторный запуск их не перезаписывает.
Пошаговая инструкция: [docs/advanced-cleaning-manual.md](docs/advanced-cleaning-manual.md).

## Ручная проверка и LibreOffice Calc

После `python examples/generate_samples.py` и `python -m excel_toolkit`:

1. Откройте `cleaner_demo.xlsx`, лист «Клиенты», оставьте все операции включёнными.
2. Запустите анализ. Ожидаемый отчёт: **5 → 3 строки**, **1** пустая строка,
   **1** дубликат удалены, **3** ячейки обрезаны, найден **1** пропуск.
3. Во вкладках сравните `" 001234 "` с `"001234"`; исходная вкладка сохраняет пробелы.
4. Сохраните результат под новым именем и откройте его в LibreOffice Calc.
   Проверьте текстовые ID `001234`, `000007` и неизменность листа «Справочник».
5. Измените checkbox: сохранение должно стать недоступным до следующего анализа.
6. Повторите с `cleaner_demo.csv`. В диалоге импорта Calc выберите разделитель `;`
   и **тип «Текст» для столбца ID**. CSV не хранит типы, и автоопределение Calc может
   убрать ведущие нули. Файл Cleaner сохраняет их буквально.
7. Проверьте ошибку сохранения поверх оригинала/существующего файла, затем выберите
   свободное имя. Для безопасного отказа откройте отдельную XLSX с объединёнными ячейками:
   предпросмотр возможен, анализ должен сообщить об ограничении и отключить экспорт.

На этапе 2B автоматически проверены Qt в offscreen-режиме и открытие экспортированных XLSX/CSV
в установленном LibreOffice через headless-конвертацию в ODS. В XLSX подтверждены
строковые ID и второй лист. Для CSV автоматический импорт Calc действительно
преобразовал ID в числа; явный текстовый импорт остаётся необходимым.
Это не ручная проверка нативного GUI и системных диалогов в Wayland/X11.
На этапе 4A LibreOffice повторно не запускался; текущие проверки перечислены ниже.

## Ограничения предпросмотра и GUI

- `.xls`, `.xlsm`, защищённые паролем книги и другие форматы не поддерживаются.
- Предпросмотр не является полной моделью книги и не пригоден для экспорта.
  Стили, объединения, изображения и оформление Excel не воспроизводятся.
- XLSX сохраняет значения, типы и числовой формат ячеек в модели предпросмотра.
  Число `12` с форматом `00000` показывается как `12`, текст `00012` — точно как `00012`.
  Формат виден во всплывающей подсказке.
- На экране длинные значения сокращаются до 2000 символов; в модели они не обрезаются.
- Автоопределение CSV — эвристика по первым 65536 символам. Неоднозначный файл
  может потребовать ручного выбора. Лимит размера поля стандартного `csv` сохранён;
  превышение вызывает ошибку, данные не обрезаются.
- Для первоначального предпросмотра читается одна дополнительная строка. Весь файл
  на этом шаге не проверяется: ошибки после предпросмотра выявляются полным анализом.
- XLSX читается в `read_only`, но openpyxl загружает метаданные, стили и shared strings.
  Одна широкая строка разбирается целиком до обрезки для GUI. Расход памяти и время
  открытия зависят от файла, фиксированный предел памяти не гарантируется.
- Закрытие во время предпросмотра запрашивает отмену и ждёт завершения потока.
  Во время анализа/экспорта оно ждёт завершения без отмены. Параллельные задачи
  блокируются; принудительное уничтожение рабочего потока не используется.
- GUI всегда использует первую строку как заголовок; выбор ключей доступен через
  All Columns / Selected Columns. Таблицы без заголовка поддерживает Python API.
- Изменения файла внешней программой автоматически не отслеживаются. Анализ создаёт
  снимок; экспорт сохраняет именно его. Для актуального содержимого повторите анализ.
- Lock-файл зависимостей и готовый Linux-пакет пока не создаются.

Архитектура и план расширения: [docs/architecture.md](docs/architecture.md).


## Cleaner: Python API (этап 2A)

Для данных в памяти используйте полную `Table` из существующих `Cell`:

```python
from excel_toolkit.application.models import Cell
from excel_toolkit.modules.cleaner import CleaningPlan, Table, clean

source = Table(
    tuple(
        tuple(Cell(value) for value in row)
        for row in [
            ["ID", "Имя"],
            [" 001234 ", " Анна "],
            ["001234", "Анна"],
            [" ", ""],
            ["000007", ""],
        ]
    )
)
plan = CleaningPlan(
    trim_whitespace=True,
    remove_empty_rows=True,
    remove_duplicates=True,
    detect_missing_values=True,
    missing_detail_limit=1000,
)
result = clean(source, plan)
print([[cell.value for cell in row] for row in result.table.rows])
# [['ID', 'Имя'], ['001234', 'Анна'], ['000007', '']]
print(result.report)
preview = result.preview(limit=100)  # Только срез уже рассчитанного результата.
```

Результат примера: 5 → 3 строки, удалена 1 пустая строка и 1 дубликат,
изменены 3 текстовые ячейки, найден 1 пропуск (`row=3, column=2, source_row=5`).
Исходная таблица неизменна. Строки отчёта включают заголовок.

Для файла и безопасного экспорта:

```python
from excel_toolkit.application.cleaning import CleaningService
from excel_toolkit.infrastructure.files.cleaning import FileCleaningStorage
from excel_toolkit.modules.cleaner import CleaningError, CleaningPlan

service = CleaningService(FileCleaningStorage())
plan = CleaningPlan(
    trim_whitespace=True, remove_empty_rows=True, remove_duplicates=True, detect_missing_values=True
)
try:
    job = service.analyze("clients.xlsx", plan, sheet="Клиенты")
    print(job.result.report)
    preview = job.result.preview(100)
    service.export(job, "clients_cleaned.xlsx")  # Имя должно быть новым.
except CleaningError as error:
    print(error)
```

Для CSV: `service.analyze("clients.csv", plan,
 csv_options=CsvOptions(encoding="utf-8-sig", delimiter=";"))`, где
`CsvOptions` импортируется из `excel_toolkit.application.models`.
Выбор кодировок и разделителей совпадает с предпросмотром. Без параметра `sheet`
выбирается первый лист XLSX. За один вызов очищается один лист, остальные сохраняются.
`analyze()` ничего не записывает; `export()` — отдельный явный шаг.
`CleaningJob` хранит исходный снимок: изменение оригинала после анализа не подменит
данные при экспорте. Экспортируйте полученный job без ручного изменения его полей.

### Операции и порядок

В Python API все четыре флага `CleaningPlan()` по умолчанию **выключены**;
GUI явно передаёт значения checkbox, изначально включённых. Порядок всегда один:

1. **Trim Whitespace** — `str.strip()` только для текста; внутренние пробелы,
   числа, даты, bool, формулы и ведущие нули сохраняются. Заголовок тоже обрабатывается.
2. **Remove Empty Rows** — удаляет строки внутри логической таблицы, где все значения
   `None`, пустые строки или пробельный текст, включая Unicode-пробелы. `0`, `False`, `"0"` не пусты.
3. **Remove Duplicates** — оставляет первое вхождение каждой полностью одинаковой
   записи и исходный порядок; при Selected Columns сохраняет отличающиеся варианты.
   Регистр, Python-тип значения и тип `Cell` учитываются: `0`, `False`, `0.0`, `"0"`
   различаются. Формат чисел и стили не участвуют; оформление первого вхождения остаётся.
   `None` и `""` различаются. Отсутствующие поля коротких строк сравниваются как `Cell(None)`.
4. **Detect Missing Values** — ищет пропуски в результате, включая заголовок;
   ничего не заполняет. Координаты начинаются с 1.

`has_header=True` защищает первую строку от удаления и исключает её из сравнения
дубликатов. Для таблицы без заголовка задайте `has_header=False`.
`duplicate_columns=(0, 2)` группирует по выбранным столбцам, индексы с нуля;
удаление требует совпадения значений всей строки.
`duplicate_columns=None` сравнивает все столбцы; пустой кортеж недопустим.
При выбранных ключах строки с отсутствующими ключевыми значениями сохраняются и
попадают в Issues. Например, `" a "` и `"a"` становятся
дубликатами после Trim: переставлять операции нельзя.

### Отчёт и предпросмотр

`CleaningReport` содержит `original_rows`, `final_rows`, `removed_empty_rows`,
`removed_duplicates`, `changed_text_cells`, `missing_values`, `warnings` и
`performed_operations`. Последнее поле перечисляет включённые операции в порядке
выполнения, даже если конкретная операция ничего не изменила.
Счётчик Trim включает изменения ячеек в строках, удалённых последующими операциями.

`missing_details` содержит `MissingValue(row, column, source_row)`; по умолчанию
сохраняются первые 1000 проблем. `missing_detail_limit=0` отключает подробности,
но сохраняет полный счётчик. `missing_details_truncated` и предупреждение указывают
на усечение списка. `source_rows` результата связывает итоговые строки с исходными.

Отчёт также содержит фактически сравниваемые `duplicate_columns`, полные счётчики
`duplicate_group_count`, `conflicting_duplicate_groups`, `missing_key_rows`,
`issue_count` и ограниченные `duplicate_groups` / `issues`.
`duplicate_group_count` считает повторяющиеся ключи, `removed_duplicates` — только
удалённые идентичные записи, `conflicting_duplicate_groups` — сохранённые конфликты.
`DuplicateGroup` хранит ключ, первую строку и её значения, примеры исходных удаляемых
строк и их значений, полный `removed_count` и индексы `conflicting_columns` с нуля.
`retained_source_rows` / `retained_values` показывают сохранённые варианты, включая первый,
`retained_count` — их полное число; `status` обозначает конфликт или идентичные повторы.
`DataIssue(source_row, column, kind)` использует координаты с единицы. Параметры плана
`duplicate_detail_limit=100`, `duplicate_row_detail_limit=20`, `issue_detail_limit=100`
ограничивают только подробности, не полные счётчики. Для сохранённых вариантов первая
строка показывается дополнительно к лимиту. Нулевые лимиты не влияют на сохранность
конфликтных записей и предупреждение о неразрешённых конфликтах.

Для XLSX границы — прямоугольник от A1 до последней ячейки со значением, текстом
или формулой. Пустые строки внутри входят в данные, оформление далеко за пределами
значений не расширяет область поиска пропусков. В CSV учитываются все записи и
максимальная ширина записи; короткие строки не дополняются при экспорте, но их
отсутствующие поля учитываются при анализе. Поиск использует ширину исходной таблицы.

Маленький предпросмотр файла по-прежнему получает `PreviewService`: он читает
ограниченную область. `CleaningService.analyze()` читает полный набор данных и
проверяет книгу; его не следует вызывать только ради первых 100 строк.
`Preview` не принимается движком и не используется для экспорта.

### Правила подсчёта строк XLSX (этап 3B)

Числа отчёта относятся к **логической таблице**, включая заголовок, а не к числу
XML-элементов `row`, `worksheet.max_row` или последней форматированной строке Excel.
Нижняя/правая границы определяются по координатам ячеек с XML-элементами `v`, `is`
или `f`. Само наличие такого элемента считается явно сохранённым содержимым,
даже для пустого `v`/`is` или пробельного текста. Это консервативное правило не менялось
в этапе 3B. Границы могут зависеть от того, как производитель записал пустую ячейку.

| Вид строки | Входит в счётчики | Remove Empty Rows / экспорт |
| --- | --- | --- |
| Строка с данными или формулой | Да | Сохраняется; формулы блокируют удаление строк книги |
| Пустая строка в начале/середине диапазона | Да, даже без физического `row` | Удаляется вместе с оформлением; первая строка защищена при `has_header=True` |
| Последняя строка с пробельным текстом или пустым `v`/`is` | Да | Удаляется и учитывается в Removed Empty Rows |
| Физический пустой `row` или `c` без `v`/`is`/`f` после диапазона | Нет | Сохраняется; отчёт явно предупреждает о количестве таких XML-строк |
| Оформление/высота строк после диапазона | Нет | Сохраняется и сдвигается на число удалённых строк выше |
| Строки, указанные только в `dimension` | Нет | Не создаются и не добавляются в счётчики |

Всегда выполняется `Original Rows − Removed Empty Rows − Removed Duplicates = Cleaned Rows`.
Удалённые физические строки **внутри** таблицы отсутствуют в экспортированном XML.
Пустой хвост **вне** таблицы не объявляется удалённым. Его наличие теперь видно в
`warnings`, которые уже отображаются в Cleaning Summary; GUI не менялся.
Предпросмотр до анализа читает физические XML-строки и может показывать иной диапазон.
После анализа обе вкладки строятся из логических таблиц исходного снимка и результата.
Счётчик Cleaned Rows описывает результат текущей операции. Если после удаления данных
остаётся только защищённый пустой заголовок без `v`/`is`/`f`, его `row` сохраняется
и Cleaned Rows равен 1; новое чтение определит уже пустую таблицу (0 строк).

На воспроизводимом образце с 10 000 клиентами, 400 дубликатами, 199 внутренними пустыми
строками и последним `<row r="10601"/>` результат — `10600 / 199 / 400 / 10001`.
Последний `row` остаётся за таблицей с номером 10002; это не удалённая строка отчёта.
При замене его на строку с пробелом — `10601 / 200 / 400 / 10001`; эта строка физически
удаляется. Закрепление не влияет на эти числа. Исходный клиентский файл не предоставлен,
поэтому это доказательство механизма, а не подтверждение структуры именно того файла.

### Безопасность и ограничения Cleaner

- Экспорт только в исходный формат: XLSX → XLSX, CSV → CSV. Конвертация отключена,
  чтобы не терять типы, листы и оформление. Произвольная `Table` в памяти предназначена
  для анализа; файловый экспорт работает с `CleaningJob` файлового сценария.
- XLSX: поддерживаются простые табличные книги, несколько листов, обычные стили,
  размеры строк/столбцов, числовые форматы, обычные закрепления и простые формулы.
  Подробности закрепления и отказов — в разделе XLSX Compatibility ниже. openpyxl используется
  для чтения значений, **не для пересохранения книги**. Меняется XML выбранного листа;
  содержимое остальных ZIP-частей копируется побайтно. ZIP-контейнер в целом не обязан
  быть побитовой копией. При удалении строки её оформление удаляется вместе с ней;
  оформление оставшихся строк сдвигается вместе с данными.
- Сложные структуры отклоняются даже на невыбранном листе: объединения, Excel Tables,
  именованные диапазоны (включая области печати), фильтры, split/frozenSplit, группировки,
  защита, условное форматирование, проверки данных, комментарии, гиперссылки,
  рисунки, диаграммы, внешние связи, макросы и неизвестные ZIP/XML-расширения.
  Rich text, shared/array/data-table formulas, UTF-16 XML и текстовые OOXML escape-
  последовательности `_xHHHH_` также пока не поддерживаются. Это намеренно узкий профиль,
  а не гарантия поддержки всех возможностей Excel или всех производителей XLSX.
  Если различные числовые значения/даты превращаются при чтении в одинаковые значения
  Python (например, серийные даты Excel 59 и 60 или округлённые доли секунды), анализ
  отклоняется, чтобы не получить ложные дубликаты.
- При формулах на любом листе фактическое удаление строк запрещено. Trim и анализ
  допустимы; формулы не меняются и не вычисляются. Формулы в ручной `Table` должны быть
  помечены `Cell("=A1", data_type="f")`. У текстовых значений `=...` в XLSX сохраняется
  строковый тип, включая значения, начинающиеся с `=` после Trim.
- Кэш формул сохраняется без пересчёта. После изменения зависимых текстовых ячеек
  вычисленные значения могут устареть; отчёт предупреждает об этом. Пересчёт ссылок
  и формул, расширение поддержки структур — отдельная будущая работа.
- CSV сохраняет Unicode, значения строк, ведущие нули, разделитель и кодировку;
  кавычки и переводы строк записывает стандартный `csv.writer`. Файл не обязан быть
  побитовой копией. CSV не хранит типы: Excel/Calc при открытии может сам преобразовать ID
  в числа или интерпретировать `=`, `+`, `-`, `@` как выражения. Cleaner не выполняет
  содержимое и не добавляет апострофы, меняющие данные; импортируйте столбцы как текст.
- Запрещены оригинал, существующий путь, hard link и symlink на занятое имя.
  Файл сначала полностью записывается во временный файл в том же каталоге, затем
  публикуется через исключительное создание hard link. Гонка с другим писателем
  не приводит к перезаписи. При обычной ошибке временный файл удаляется, частичный
  конечный файл не появляется. Файловая система должна поддерживать hard links.
- Принудительное завершение процесса/сбой питания может оставить временный файл;
  устойчивость к аварийному отключению питания и враждебной смене каталогов не
  гарантируется. Исходный файл движок никогда не открывает на запись.
- Лимиты полного анализа: XLSX до 128 MiB, до 256 MiB распакованных частей и 1000
  ZIP-записей; прямоугольник данных до 2 000 000 ячеек для CSV/XLSX. Превышение — ошибка,
  не обрезка данных. Анализ держит таблицу в памяти; это не потоковый движок для
  неограниченных файлов. Стандартный лимит размера CSV-поля сохранён.

Этап 2B подключает `CleaningService` к GUI: выбор операций, фоновый анализ, отчёт,
предпросмотр и отдельное действие экспорта. Точных процентов прогресса и отмены
полного анализа Cleaner пока нет; используется неопределённый индикатор.
Существующая отмена предпросмотра работает как раньше.

## XLSX Compatibility

Cleaner поддерживает обычные табличные XLSX: несколько листов, текстовые ID с ведущими
нулями, числа, bool, даты, текст, обычные стили, размеры строк/столбцов и простые формулы.
При экспорте изменяется только XML выбранного листа; остальные части ZIP копируются
с сохранением несжатых байтов, в том числе стили и relationships. XLS/XLSM не поддерживаются.

### Закреплённые строки и столбцы

Поддерживается `sheetViews/sheetView/pane` со `state="frozen"` в обычном виде листа
с направлением слева направо: первая строка (`A2`), первый столбец (`B1`), несколько
строк (`A4`), строки и столбцы одновременно (`C4`). Проверяются структура XML,
целочисленные `xSplit`/`ySplit`, границы координат, `topLeftCell`, `activePane` и `selection`.
`pane` сохраняется; Cleaner не удаляет закрепление ради успешного анализа.

- Trim и анализ без фактического удаления строк сохраняют настройки представления.
- При удалении строк **внутри закреплённой области** анализ отклоняется: программа
  не выбирает новую границу закрепления за пользователя.
- При удалении ниже этой области сохраняются число закреплённых строк/столбцов и
  активная область. Координаты прокрутки (`sheetView.topLeftCell`, `pane.topLeftCell`),
  активной ячейки и диапазонов выделения сдвигаются вслед за сохранившимися строками.
- Если удаляется сама координата прокрутки/активной ячейки или строка внутри выделения
  `sqref`, операция отклоняется. Даже удаление пустой строки непосредственно под
  закреплением может попасть под это ограничение, если на неё указывает `topLeftCell`.
  Можно отключить удаление строк либо осознанно изменить выделение/прокрутку/закрепление
  в Excel и повторить анализ. Это консервативное ограничение, не признак повреждения файла.
- `split`, `frozenSplit`, нестандартные свойства, неверные координаты и неподдерживаемый
  вид закреплённого листа отклоняются, в том числе на других листах. Корректные закрепления
  других листов сохраняются без изменений. Проверка представлений действует и без `pane`.

### featurePropertyBag и остальные ограничения

`xl/featurePropertyBag/featurePropertyBag.xml` пока **отклоняется** с отдельным объяснением.
Компонент не удаляется и не добавлен в разрешённый список. Он может хранить типизированные
свойства, ссылки на другие наборы свойств и relationships. Например, цепочка
`XFComplements → XFComplement → XFControls → Checkbox` описывает оформление элементов
управления в ячейках; стили ссылаются на неё через `xfComplement`. Это содержимое не следует
считать необязательным мусором. См. [спецификацию Feature Property Bag](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-xlsx/19ef002a-0b33-45b3-aa01-fcae807602ff)
и [связи со стилями](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-xlsx/d6ffbc21-ef11-4546-9a07-95885e2fd497).

Нынешний ZIP-экспорт технически способен копировать такой компонент, но проверки типов
свойств, индексов и связей со стилями ещё нет. Само копирование не доказывает корректность
очистки. Даже пустой bag и известный checkbox-профиль пока отклоняются. Эксперимент
с openpyxl 3.1.5 также показал, что обычное `load_workbook()` → `save()` теряет компонент
и `xfComplement`, а также relationship и Content-Type; этот способ не используется нашим
экспортом. Потеря проверяется отдельным регрессионным тестом на настоящем OOXML-пакете.

В этапе 3B дополнительно закрыт обход проверки: ссылка `xfComplement`/`DXFComplement`
или объявление Content-Type без самой части теперь тоже вызывает отказ. Неизвестные
расширения стилей (`extLst`, чужие XML-пространства и расширенные атрибуты) отклоняются.
Ранее некоторые такие неполные пакеты могли проходить анализ — это намеренное усиление
проверок, не новая поддержка bag.

Простое копирование bag не делает удаление строк безопасным: по
[MS-XLSX Checkbox](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-xlsx/00b82621-5aa1-4ea8-b251-7b7a51242610)
элемент управления допускает пустое значение (`default=2`). Такая ячейка может быть
значимой, хотя обычный Cleaner видит `None`. Даже пустой bag требует доказать отсутствие
всех входящих ссылок. Поддержка через исходный ZIP архитектурно возможна, но требует
отдельного валидатора графа и правил обработки ячеек с элементами управления.
Объём и риски описаны в [архитектуре](docs/architecture.md#xlsx-compatibility).
Ни чтение через openpyxl, ни сохранность произвольных байтов не считаются доказательством
безопасного экспорта. В этом этапе поддержка featurePropertyBag **не включена**.

Остальные ограничения сохранены: объединения, Tables, именованные диапазоны, фильтры,
защита, группировки, условное форматирование, проверки данных, комментарии, гиперссылки,
рисунки, диаграммы, внешние связи, макросы, rich text и неизвестные ZIP/XML-расширения
не поддерживаются. При формулах **на любом листе** удаление строк запрещено. Обычные формулы
и их кэш сохраняются без вычисления; после Trim кэш может требовать пересчёта в Excel.
Shared/array/data-table formulas по-прежнему отклоняются. Предпросмотр может работать
для неподдерживаемого файла: он не выполняет полную проверку безопасности Cleaner.

### Ручная проверка совместимости

1. Создайте небольшой XLSX с заголовком, ID `001234` именно текстового типа, числами,
   датами, пустой строкой и дубликатом. Добавьте второй лист с контрольными значениями.
2. Закрепите первую строку, оставьте выделение `A1`, прокрутку у начала таблицы.
   Пустую строку и дубликат разместите ниже первой строки данных, чтобы не удалять `A2`.
3. Откройте файл в приложении, выполните Analyze & Clean и сохраните в новое имя.
   В Excel/Calc проверьте закрепление, порядок данных, ведущие нули, типы, стили и второй лист.
4. Повторите для первого столбца, нескольких строк и одновременного закрепления.
   Дубликат внутри закреплённых строк должен вызвать объяснимый отказ; после отключения
   удаления строк Trim должен работать. `split` и файл с featurePropertyBag должны отклоняться.

Автотесты создают небольшие настоящие XLSX и проверяют CRC ZIP, XML, назначения relationships,
сохранность частей и повторное открытие через openpyxl. Это не полная XSD-валидация и не ручная
проверка Excel. Исходные два проблемных файла отсутствуют в проекте: добавьте обезличенные
копии в `tests/fixtures`, чтобы проверить именно их. Их исправление пока не подтверждено.

Для воспроизводимого замера на 10 000 записях: `python examples/benchmark_xlsx.py`,
для закрепления — `python examples/benchmark_xlsx.py --freeze A2`. Результаты сравнения,
окружение и методика приведены в архитектуре.

### Ручная проверка этапа 3B

Создайте два новых образца (команды откажутся перезаписывать существующий файл):

```bash
python examples/benchmark_xlsx.py --dataset clients --freeze A2 --tail bare --repeats 1 --save-sample /tmp/clients-bare.xlsx
python examples/benchmark_xlsx.py --dataset clients --freeze A2 --tail space --repeats 1 --save-sample /tmp/clients-space.xlsx
```

В GUI включите четыре операции. Для первого ожидаются `10600 / 199 / 400 / 10001`
и предупреждение об одной строке вне диапазона, для второго — `10601 / 200 / 400 / 10001`.
Сохраните в новые файлы и снова выполните анализ: оба результата должны иметь 10001
строку, 0 пустых удалений и 0 дубликатов. Проверьте ID `000000` и `009999`, закрепление A2
и лист Other. Вариант `--tail formatted` дополнительно сохраняет оформление A10002,
поэтому `openpyxl.max_row` результата будет 10002 при логических 10001 строках.

Для featurePropertyBag откройте исходный проблемный XLSX: Analyze & Clean должен дать
объяснимый отказ, экспорт оставаться недоступным, исходный файл — неизменным.
Не пересохраняйте клиентский файл через openpyxl ради удаления компонента.
Регрессии структуры, отказов и отдельного эксперимента с потерей bag:

```bash
python -m pytest -q tests/test_xlsx_rows.py tests/test_xlsx_compatibility.py
```

Для сравнения скорости прежний профиль benchmark сохранён без смены умолчаний;
`--dataset clients` добавляет именно случай с 10 000 уникальных клиентов.
