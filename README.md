# Excel Freelancer Toolkit

Локальное desktop-приложение для Linux на Python 3.11+, PySide6 и openpyxl.
Этапы 1 и 2A: безопасный предпросмотр Excel/CSV и независимый движок Cleaner. Сервер, внешние API, платные
сервисы, pandas и ИИ не используются. Интернет нужен только для установки зависимостей.

## Возможности

- Раздел Cleaner: выбор `.xlsx` / `.csv`, листа Excel, имя файла и область ошибок.
- Первые **100 строк**, включая первую, без угадывания заголовков и удаления пустых строк.
- До **200 столбцов**; наличие дополнительных строк/столбцов отмечается в интерфейсе.
- Фоновое чтение в Qt-потоке, безопасное закрытие окна во время загрузки.
- CSV: UTF-8 с BOM и без; ручной выбор Windows-1251, Windows-1252 и UTF-16 с BOM.
- Разделители: запятая, точка с запятой, табуляция, `|`; автоопределение или ручной выбор.
- Формулы XLSX показываются как текст и не вычисляются. Значения CSV остаются строками.
- Оригиналы открываются только для чтения. Очистка и экспорт доступны через Python API;
  GUI остаётся на этапе предпросмотра. Merger и Compare пока недоступны.

## Установка в Linux

Нужен Python 3.11+ с поддержкой `venv`. В Arch Linux системный пакет называется
`python`; зависимости проекта устанавливаются в отдельное окружение:

```bash
cd /path/to/prog-excel
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

Без инструментов разработки: `python -m pip install -e .`.
Системное окружение Python менять не требуется. Зависимости и настройки проверок —
в `pyproject.toml`.

## Запуск

В активированном окружении, из терминала графической сессии Linux:

```bash
python -m excel_toolkit
```

Нажмите «Выбрать файл…». У XLSX с несколькими листами станет доступен список листов.
Для CSV по умолчанию используются UTF-8 и автоопределение разделителя. Если файл
не прочитан или разделитель распознан неверно, выберите настройки и нажмите
«Повторить загрузку». Настройки применяются и при следующем выборе файла.
Ошибочные байты не заменяются и не пропускаются.

Создание примеров без перезаписи существующих файлов:

```bash
python examples/generate_samples.py
```

Откройте `examples/generated/clients.xlsx` или `clients.csv`.
Для `clients_cp1251.csv` выберите Windows-1251.

## Тесты и качество кода

```bash
python -m pytest
ruff check .
ruff format --check .
```

Тесты генерируют таблицы во временных каталогах. GUI-тесты используют `offscreen`
и отключают тему рабочего стола, поэтому не требуют X11/Wayland или pytest-плагина.
Проверяются чтение, кодировки, разделители, формулы и типы, ведущие нули, выбор листа,
лимиты, ошибки, неизменность оригиналов, обновление GUI в главном потоке,
отзывчивость и закрытие при фоновой загрузке.

## Ограничения предпросмотра и GUI

- `.xls`, `.xlsm`, защищённые паролем книги и другие форматы не поддерживаются.
- Предпросмотр не является полной моделью книги и не пригоден для экспорта.
  Стили, объединения, изображения и оформление Excel не воспроизводятся.
- XLSX сохраняет значения, типы и числовой формат ячеек в модели предпросмотра.
  Число `12` с форматом `00000` показывается как `12`, текст `00012` — точно как `00012`.
  Формат виден во всплывающей подсказке.
- На экране длинные значения сокращаются до 2000 символов; в модели они не обрезаются.
- Автоопределение CSV — эвристика по первым 65536 символам. Неоднозначный файл
  может потребовать ручного выбора. Лимит размера поля стандартного `csv` сохранён;
  превышение вызывает ошибку, данные не обрезаются.
- Для определения продолжения читается одна дополнительная строка. Весь файл не
  проверяется: ошибки после предпросмотра могут остаться незамеченными.
- XLSX читается в `read_only`, но openpyxl загружает метаданные, стили и shared strings.
  Одна широкая строка разбирается целиком до обрезки для GUI. Расход памяти и время
  открытия зависят от файла, фиксированный предел памяти не гарантируется.
- Закрытие во время чтения запрашивает отмену и ждёт безопасного завершения потока.
  Открытие ZIP/XML и отдельное чтение нельзя прервать мгновенно. Параллельные загрузки
  блокируются; принудительное уничтожение рабочего потока не используется.
- В GUI нет сохранения и операций Cleaner. Lock-файл зависимостей и готовый Linux-пакет
  пока не создаются.

Архитектура и план расширения: [docs/architecture.md](docs/architecture.md).


## Cleaner: Python API (этап 2A)

Для данных в памяти используйте полную `Table` из существующих `Cell`:

```python
from excel_toolkit.application.models import Cell
from excel_toolkit.modules.cleaner import CleaningPlan, Table, clean

source = Table(
    tuple(
        tuple(Cell(value) for value in row)
        for row in [
            ["ID", "Имя"],
            [" 001234 ", " Анна "],
            ["001234", "Анна"],
            [" ", ""],
            ["000007", ""],
        ]
    )
)
plan = CleaningPlan(
    trim_whitespace=True,
    remove_empty_rows=True,
    remove_duplicates=True,
    detect_missing_values=True,
    missing_detail_limit=1000,
)
result = clean(source, plan)
print([[cell.value for cell in row] for row in result.table.rows])
# [['ID', 'Имя'], ['001234', 'Анна'], ['000007', '']]
print(result.report)
preview = result.preview(limit=100)  # Только срез уже рассчитанного результата.
```

Результат примера: 5 → 3 строки, удалена 1 пустая строка и 1 дубликат,
изменены 3 текстовые ячейки, найден 1 пропуск (`row=3, column=2, source_row=5`).
Исходная таблица неизменна. Строки отчёта включают заголовок.

Для файла и безопасного экспорта:

```python
from excel_toolkit.application.cleaning import CleaningService
from excel_toolkit.infrastructure.files.cleaning import FileCleaningStorage
from excel_toolkit.modules.cleaner import CleaningError, CleaningPlan

service = CleaningService(FileCleaningStorage())
plan = CleaningPlan(
    trim_whitespace=True, remove_empty_rows=True, remove_duplicates=True, detect_missing_values=True
)
try:
    job = service.analyze("clients.xlsx", plan, sheet="Клиенты")
    print(job.result.report)
    preview = job.result.preview(100)
    service.export(job, "clients_cleaned.xlsx")  # Имя должно быть новым.
except CleaningError as error:
    print(error)
```

Для CSV: `service.analyze("clients.csv", plan,
 csv_options=CsvOptions(encoding="utf-8-sig", delimiter=";"))`, где
`CsvOptions` импортируется из `excel_toolkit.application.models`.
Выбор кодировок и разделителей совпадает с предпросмотром. Без параметра `sheet`
выбирается первый лист XLSX. За один вызов очищается один лист, остальные сохраняются.
`analyze()` ничего не записывает; `export()` — отдельный явный шаг.
`CleaningJob` хранит исходный снимок: изменение оригинала после анализа не подменит
данные при экспорте. Экспортируйте полученный job без ручного изменения его полей.

### Операции и порядок

Все четыре флага по умолчанию **выключены**. Порядок всегда один:

1. **Trim Whitespace** — `str.strip()` только для текста; внутренние пробелы,
   числа, даты, bool, формулы и ведущие нули сохраняются. Заголовок тоже обрабатывается.
2. **Remove Empty Rows** — удаляет строки, где все значения `None`, пустые строки
   или пробельный текст, включая Unicode-пробелы. `0`, `False`, `"0"` не пусты.
3. **Remove Duplicates** — оставляет первое вхождение и исходный порядок.
   Регистр, Python-тип значения и тип `Cell` учитываются: `0`, `False`, `0.0`, `"0"`
   различаются. Формат чисел и стили не участвуют; оформление первого вхождения остаётся.
   `None` и `""` различаются. Отсутствующие поля коротких строк сравниваются как `Cell(None)`.
4. **Detect Missing Values** — ищет пропуски в результате, включая заголовок;
   ничего не заполняет. Координаты начинаются с 1.

`has_header=True` защищает первую строку от удаления и исключает её из сравнения
дубликатов. Для таблицы без заголовка задайте `has_header=False`.
`duplicate_columns=(0, 2)` ограничивает сравнение выбранными столбцами, индексы с нуля.
По умолчанию сравниваются все столбцы. Например, `" a "` и `"a"` становятся
дубликатами после Trim: переставлять операции нельзя.

### Отчёт и предпросмотр

`CleaningReport` содержит `original_rows`, `final_rows`, `removed_empty_rows`,
`removed_duplicates`, `changed_text_cells`, `missing_values`, `warnings` и
`performed_operations`. Последнее поле перечисляет включённые операции в порядке
выполнения, даже если конкретная операция ничего не изменила.
Счётчик Trim включает изменения ячеек в строках, удалённых последующими операциями.

`missing_details` содержит `MissingValue(row, column, source_row)`; по умолчанию
сохраняются первые 1000 проблем. `missing_detail_limit=0` отключает подробности,
но сохраняет полный счётчик. `missing_details_truncated` и предупреждение указывают
на усечение списка. `source_rows` результата связывает итоговые строки с исходными.

Для XLSX границы — прямоугольник от A1 до последней ячейки со значением, текстом
или формулой. Пустые строки внутри входят в данные, оформление далеко за пределами
значений не расширяет область поиска пропусков. В CSV учитываются все записи и
максимальная ширина записи; короткие строки не дополняются при экспорте, но их
отсутствующие поля учитываются при анализе. Поиск использует ширину исходной таблицы.

Маленький предпросмотр файла по-прежнему получает `PreviewService`: он читает
ограниченную область. `CleaningService.analyze()` читает полный набор данных и
проверяет книгу; его не следует вызывать только ради первых 100 строк.
`Preview` не принимается движком и не используется для экспорта.

### Безопасность и ограничения Cleaner

- Экспорт только в исходный формат: XLSX → XLSX, CSV → CSV. Конвертация отключена,
  чтобы не терять типы, листы и оформление. Произвольная `Table` в памяти предназначена
  для анализа; файловый экспорт работает с `CleaningJob` файлового сценария.
- XLSX: поддерживаются простые табличные книги, несколько листов, обычные стили,
  размеры строк/столбцов, числовые форматы и простые формулы. openpyxl используется
  для чтения значений, **не для пересохранения книги**. Меняется XML выбранного листа;
  содержимое остальных ZIP-частей копируется побайтно. ZIP-контейнер в целом не обязан
  быть побитовой копией. При удалении строки её оформление удаляется вместе с ней;
  оформление оставшихся строк сдвигается вместе с данными.
- Сложные структуры отклоняются даже на невыбранном листе: объединения, Excel Tables,
  именованные диапазоны (включая области печати), фильтры, закрепления, группировки,
  защита, условное форматирование, проверки данных, комментарии, гиперссылки,
  рисунки, диаграммы, внешние связи, макросы и неизвестные ZIP/XML-расширения.
  Rich text, shared/array/data-table formulas, UTF-16 XML и текстовые OOXML escape-
  последовательности `_xHHHH_` также пока не поддерживаются. Это намеренно узкий профиль,
  а не гарантия поддержки всех возможностей Excel или всех производителей XLSX.
  Если различные числовые значения/даты превращаются при чтении в одинаковые значения
  Python (например, серийные даты Excel 59 и 60 или округлённые доли секунды), анализ
  отклоняется, чтобы не получить ложные дубликаты.
- При формулах на любом листе фактическое удаление строк запрещено. Trim и анализ
  допустимы; формулы не меняются и не вычисляются. Формулы в ручной `Table` должны быть
  помечены `Cell("=A1", data_type="f")`. У текстовых значений `=...` в XLSX сохраняется
  строковый тип, включая значения, начинающиеся с `=` после Trim.
- Кэш формул сохраняется без пересчёта. После изменения зависимых текстовых ячеек
  вычисленные значения могут устареть; отчёт предупреждает об этом. Пересчёт ссылок
  и формул, расширение поддержки структур — отдельная будущая работа.
- CSV сохраняет Unicode, значения строк, ведущие нули, разделитель и кодировку;
  кавычки и переводы строк записывает стандартный `csv.writer`. Файл не обязан быть
  побитовой копией. CSV не хранит типы: Excel при открытии может сам преобразовать ID
  в числа или интерпретировать `=`, `+`, `-`, `@` как выражения. Cleaner не выполняет
  содержимое и не добавляет апострофы, меняющие данные; импортируйте столбцы как текст.
- Запрещены оригинал, существующий путь, hard link и symlink на занятое имя.
  Файл сначала полностью записывается во временный файл в том же каталоге, затем
  публикуется через исключительное создание hard link. Гонка с другим писателем
  не приводит к перезаписи. При обычной ошибке временный файл удаляется, частичный
  конечный файл не появляется. Файловая система должна поддерживать hard links.
- Принудительное завершение процесса/сбой питания может оставить временный файл;
  устойчивость к аварийному отключению питания и враждебной смене каталогов не
  гарантируется. Исходный файл движок никогда не открывает на запись.
- Лимиты полного анализа: XLSX до 128 MiB, до 256 MiB распакованных частей и 1000
  ZIP-записей; прямоугольник данных до 2 000 000 ячеек для CSV/XLSX. Превышение — ошибка,
  не обрезка данных. Анализ держит таблицу в памяти; это не потоковый движок для
  неограниченных файлов. Стандартный лимит размера CSV-поля сохранён.

Этап 2B может подключить `CleaningService` к GUI: выбор операций, фоновый анализ,
отчёт, предпросмотр и отдельное действие экспорта. Прогресс и отмена полного анализа
Cleaner пока не реализованы; существующая отмена предпросмотра работает как раньше.
